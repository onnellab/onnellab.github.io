# 研究の読書記録を長く使える形で残す方法

研究の読書記録は、他の人も出典・根拠・解釈と主張の関係を確認できる形で残します。PDFやハイライトだけでは、リンクや文脈の変化で意味が失われます。

## 質問

プロジェクト終了後も役立つ研究の読書記録は、どう残せばよいですか？

## 短い答え

識別情報、根拠の位置、参照日、誤読を防ぐ文脈を記録します。引用と言い換えを区別し、主張や問いに結び付けます。収集、検証、要約、統合、確認を経て、公開仕様の形式で書き出し、独立したバックアップと引き継ぎ資料を作ります。

ハイライトより、追跡できる関係を残します。

**出典 → 記述または結果 → 解釈 → プロジェクトの主張 → 確認状況**

## 読書記録が役立たなくなる理由

内容だけでは、由来する資料・版が分かりません。ページのない引用、出版社トップだけを指すURL、原文と紛らわしい言い換えが例です。大まかなタグは主張へのリンクに代わらず、DOIも文脈や本文閲覧を保証しません。

**出典の持続性**は所在が変わっても資料を特定できること、**解釈の持続性**は観察・表現・重要とした理由が分かることです。識別子は前者を、読書記録は後者を支えます。

## 長く使える最小限の記録スキーマ

版ごとに記録します。大幅な変更は上書きせず、新規記録で版同士を結び付けます。

| フィールド | 記録する内容 | 必要な理由 |
| --- | --- | --- |
| `record_id` | `RL-2026-0042`などの不変ID | 内部リンクを安定させる |
| `source_identity` | 著者、タイトル、収録媒体、日付、版 | 参照資料を特定 |
| `stable_identifier` | 完全な`https://doi.org/...` URLや登録識別子 | 識別情報と所在を分離 |
| `locator` | 参照URL、ページ、節、図、タイムスタンプ、データ行 | 根拠の位置を特定 |
| `accessed_at` | `YYYY-MM-DD`形式の日付 | 変動するウェブ資料の参照日 |
| `note_type` | `quote`、`paraphrase`、`summary`、`observation` | 自分の言葉と原文を区別 |
| `evidence` | 短い引用、言い換え、結果、観察 | 根拠を保存 |
| `context` | 対象集団、方法、条件、例外 | 適用範囲の誤りを防止 |
| `claim_link` | 関連する主張、問い、主張ID | 主張との関係を確認 |
| `relevance` | 根拠が重要な理由 | 判断過程を保存 |
| `status` | `captured`、`verified`、`summarized`、`synthesized`、`reviewed`、`needs_review` | 確認済み・未確認を明示 |
| `tags` | 主題、方法、対象集団、プロジェクトの統制語彙 | 検索を支援 |

権利、言語、チェックサム、保存先、矛盾・関連記録は任意項目です。空欄ばかりのスキーマより、毎回埋まる小さなものを選びます。

## 直接引用、言い換え、要約、観察を区別する

収集時に表現方法を明示します。

- **直接引用（quote）**：原文の再現。引用符と正確な位置が必要です。
- **言い換え（paraphrase）**：自分の言葉での再述。出典と位置は必要です。
- **要約（summary）**：広い範囲の圧縮。対象範囲も記録します。
- **観察（observation）**：自分の分析と明示し、元データの位置を残します。

引用の省略・変更は明示してください。PDFは記載されたページ番号があればそれを使い、HTMLは安定した見出し、音声・映像は時間範囲、データセットは版・表・変数・該当行やクエリを記録します。

## 出典だけでなく、主張と根拠を結び付ける

参考文献は読んだ資料を、根拠とのリンクはその役割を示します。重要な主張に不変IDを付け、根拠が**支持する**、**条件を限定する**、**反証する**、**背景のみを提供する**のか明示します。隣接する引用がすべて同じ主張を支持する、という誤解を防げます。

標本、地域、期間、方法、不確実性、比較対象、著者の留保は結果の適用範囲を左右するため、根拠の隣に残します。「成人の同じ評価項目だが追跡は7日間」は「重要な論文」より有用です。

## 推奨ワークフロー

1. **収集する。** 出典を開いている間に、書誌情報、識別子、実際の参照URL・日付、根拠の位置、メモの種類、最小限の根拠、内部IDを記録します。
2. **検証する。** 識別子を解決し、著者、タイトル、日付、版、収録媒体を登録機関や出版社の記録と照合します。根拠を開き直し、引用を一字ずつ確認してください。リンクが開くだけでは版の正確さは分かりません。
3. **要約する。** 問い、方法、結果、限界を自分の言葉で、引用とは分けて記録します。読み直さないと説明できなければ、統合はまだ早い段階です。
4. **統合する。** 主張や他の記録に結び付け、一致、方法・対象による差、矛盾を説明します。不一致を曖昧な平均的結論で消さないでください。
5. **確認する。** 公開・引き継ぎ前に重要な主張、識別子、リンク、引用範囲、位置、権利、個人情報、状態を再確認します。確認済みは`reviewed`、未解決は`needs_review`とし、未検証を明示します。

![研究の読書記録を長く使うための4つの確認事項](/blog-assets/ja/keep-durable-research-reading-log/workflow-diagram.svg "出典の情報と根拠の位置を残し、引用と解釈を分け、内容を再確認する")

根拠不足や新版が見つかれば収集・検証に戻ります。状態は処理段階を示し、出典の権威ではありません。

## 安定した識別子とリンクの限界

DOIがあれば優先し、`https://doi.org/10.xxxx/xxxxx`のような完全なURLで示します。参照したコピー、リポジトリ、案内ページを特定する実際のURLも別に残します。

持続性は登録情報の維持に依存し、閲覧権限、補足資料の不変性、引用ページの提供は保証しません。登録識別子がなければ全書誌情報、版、URL、参照日を残し、必要に応じて許可されたコピーを保存します。

読んだ版を特定し、版同士を関連付けます。引用、ページ、結果が同じと仮定してプレプリントを最終論文の記録に置き換えてはいけません。

## 著作権とプライバシーへの配慮

記録作成は複製の許可ではありません。最小限の抜粋に出典と位置を残し、全文再配布ではなく正規のコピーにリンクします。著作権の例外は地域・目的で異なり、米国著作権局も安全な固定語数や割合を示していません。共有前にライセンス、組織の方針、適用法を確認してください。

メモにはインタビューの引用、参加者ID、メール、健康情報、機微な評価も含まれ得ます。収集を抑え、アクセス制限資料を分離し、適切なら仮名化IDを使い、秘密情報を除いて書き出します。目的に適切で関連し、必要な情報だけを残すデータ最小化の原則は、EU一般データ保護規則の適用外でも参考になります。

## 書き出し、バックアップ、復元

特定アプリに依存せず読めるよう、定期的に、また主要な節目に、文書化された形式で書き出します。

| 形式 | 適した用途 | 保存時の注意点 |
| --- | --- | --- |
| UTF-8テキスト・Markdown | 人が読む記録・要約 | リンクとフィールド名を明示し、独自拡張を避ける |
| CSV | 表・スプレッドシート間の交換 | 文字コード、区切り、改行、リストのエスケープを文書化 |
| JSON | 構造化フィールド・配列・機械処理 | ファイル検証とデータ辞書の保存 |
| PDF/A・検索可能PDF | 確認・引き継ぎ時の固定コピー | 編集・機械処理用の唯一の原本にしない |

作業システムから独立したコピーがバックアップです。複数の保存先に記録と許可された添付を保存し、定期的に空のフォルダーへ一部を復元します。識別子、Unicode、改行、記録間の関係を確認してください。チェックサムは変更を検出しますが、引用の正確さや記録の完全性は証明しません。

ファイル名は`RL-2026-0042.md`のようにIDを使います。マニフェストに記録数、書き出し日、スキーマの版、添付・除外資料、チェックサム方式を記載します。米国議会図書館も長期保存・アクセスを考慮した形式選択を勧めています。公開・文書化された形式はベンダー依存を減らしますが、点検・移行は必要です。

## プロジェクト終了時の引き継ぎ

元のソフトウェアや担当者の記憶に頼らず使える資料を用意します。

1. 人が読める形式と構造化形式、各一つ以上の記録
2. 問い、範囲、期間、スキーマ、状態の意味、タグ語彙、フォルダー構成を示すREADME
3. 主要な主張と、支持・限定・反証する記録を結ぶ索引
4. ファイル、版、チェックサム、ライセンス、アクセス制限のマニフェスト
5. `needs_review`、切断・制限付きリンク、欠落出典、未解決の不一致の一覧
6. 最終復元確認日・方法、次回確認の担当者・予定日

未解決と分かる記録の方が、根拠を回復できない整った結論より安全です。

## まとめ

出典・版、引用と解釈、根拠と主張の関係、限界・確認状況を残します。公開形式の出力、復元確認済みバックアップ、引き継ぎ資料で、元のプロジェクトやソフトウェアがなくても判断過程を再利用できます。

## よくある質問

### DOIがあれば、読書記録を長く使えますか？

不十分です。DOIによる出典特定・解決に加え、版、位置、参照日、文脈、主張との関係、確認状況も必要です。適法なバックアップの代わりにはならず、本文閲覧も保証しません。

### ハイライトをすべて記録にするべきですか？

いいえ。問い、方法の選択、主張に関わる根拠を選びます。無選別のハイライトは確認負担を増やし、重要な根拠を埋もれさせます。

### 言い換えた場合も、ページや節の記録は必要ですか？

必要です。原文の文脈と比較できる正確な位置を残します。

### リンクが切れたら、どうすればよいですか？

識別子を解決し、登録情報や公式リポジトリを探します。旧参照履歴を残して位置を追加し、回復不能なら`needs_review`と記して重要な主張に使わないでください。

### どのくらいの頻度で記録を見直せばよいですか？

統合前、影響の大きい公開前、引き継ぎ時に確認します。変動するウェブ資料や更新型データセットは定期的にも再確認します。
