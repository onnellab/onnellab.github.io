# 如何建立長期可用的研究閱讀紀錄

長期可用的研究閱讀紀錄，能讓他人辨識來源、找回證據、理解你的解讀及其與論點的關係。只存 PDF 和重點標示，容易在連結或脈絡改變後失去意義。

## 要解決的問題

如何維護一份在專案結束後仍然有用的研究閱讀紀錄？

## 簡短回答

為每個來源保留穩定識別資訊、證據位置和存取日期，區分直接引用與改寫，將筆記連結到具體論點或研究問題，並保留足夠脈絡以免誤讀。讓紀錄依序經過蒐集、查證、摘要、綜整與複核，再匯出為規格公開且有文件說明的格式，建立獨立備份，並撰寫交接說明。

要長期保留的不只是重點標示，還有可追溯的關係：

**來源 → 原文段落或結果 → 解釋 → 專案論點 → 複核狀態**

## 閱讀紀錄為什麼會逐漸失去用途

追溯來源，就是確認資料和版本。不完整的紀錄只留內容，丟失了這條線索。例如，引文沒有頁碼，URL 只指向出版社首頁，或者改寫的句子看起來像作者的原話。籠統的標籤無法取代與具體論點的關聯；DOI 也無法保住所讀版本的脈絡，更不能保證全文始終可存取。

**來源的可追溯性**，指位置改變後仍能辨識資料。**解釋的可理解性**，指日後仍能看懂你的觀察、表述及其重要性。穩定識別碼有助於前者，閱讀紀錄保留後者。

## 長期可用紀錄的最小欄位結構

每個來源版本建立一筆紀錄。論文、資料集、報告或預印本有實質變動時，應新增紀錄並連結不同版本，不要直接覆寫舊筆記。

| 欄位 | 記錄內容 | 用途 |
| --- | --- | --- |
| `record_id` | `RL-2026-0042` 這類不變的 ID | 保持內部連結穩定 |
| `source_identity` | 作者、標題、刊載期刊等載體、日期、版本 | 辨識實際查閱的資料 |
| `stable_identifier` | 完整的 `https://doi.org/...` URL 或其他註冊識別碼 | 將資料身分與存放位置分開 |
| `locator` | 存取 URL，以及頁碼、章節、圖號、時間戳記或資料列 | 重新找到來源中的證據 |
| `accessed_at` | `YYYY-MM-DD` 格式的完整日期 | 記錄何時查看過可能變動的網頁資料 |
| `note_type` | `quote`、`paraphrase`、`summary` 或 `observation` | 區分原文與自己的表述 |
| `evidence` | 簡短引文、改寫、結果或觀察 | 保留相關證據 |
| `context` | 研究族群、方法、條件、例外 | 減少適用範圍的判斷錯誤 |
| `claim_link` | 相關論點、問題或論點 ID | 讓證據與論點的關係可以查核 |
| `relevance` | 這項證據為什麼重要 | 保留專案中的推理過程 |
| `status` | `captured`、`verified`、`summarized`、`synthesized`、`reviewed` 或 `needs_review` | 顯示哪些內容已檢查，哪些尚未檢查 |
| `tags` | 用詞統一的主題、方法、族群或專案標籤 | 方便搜尋 |

也可以視需要加入權利、語言、檢查碼、封存位置、衝突及相關紀錄等欄位。每次都能填完整的小型結構，比大部分欄位空白的龐大結構更實用。

## 區分直接引用、改寫、摘要和觀察

蒐集資料時，就應明確標記採用了哪一種表述方式。

- **直接引用（quote）**逐字保留原文，需要引號與精確位置。
- **改寫（paraphrase）**用自己的話重述某個段落，仍然需要註明來源和位置。
- **摘要（summary）**濃縮較大範圍的內容，需要記下涵蓋的範圍。
- **觀察（observation）**屬於你自己的分析，應清楚標註，並保留原始資料的位置。

引用中的省略或更動都要標明。PDF 有印刷頁碼時，應使用該頁碼；HTML 使用相對穩定的標題；音訊和影片使用起訖時間戳記；資料集則記錄版本、表格、變數，以及相關資料列或查詢條件。

## 將論點與證據連結，而不只是列出來源

參考文獻說明你讀過什麼，論點與證據的關聯則說明這些閱讀發揮了什麼作用。為重要論點分配穩定的內部 ID，並在每筆紀錄中說明，證據是**支持論點**、**限定其適用條件**、**反駁論點**，還是僅僅**提供背景**。這樣可避免將相鄰的多個引用都呈現為某項論述的支持依據，實際上卻只有一個來源真正支持它。

把限制條件寫在證據旁邊。樣本、地區、時間範圍、方法、不確定性、比較組，以及作者提出的保留意見，都會影響研究結果能否用於其他情境。「探討成人的同一結果指標，但追蹤只有七天」，比「重要論文」更有用。

## 建議工作流程

1. **蒐集。** 在來源仍開啟時，記下書目資訊、識別碼、實際存取 URL 和日期、證據位置、筆記類型，以及足夠且必要的最少證據，並分配內部 ID。
2. **查證。** 檢查識別碼能否解析至對應資料；DOI 可透過 `https://doi.org` 解析。將作者、標題、日期、版本和載體與註冊機構或出版社的官方紀錄比對，再重新開啟證據位置，逐字核對引文。連結能開啟，不代表版本和中繼資料正確。
3. **摘要。** 用自己的話分別寫出問題、方法、結果和限制，與直接引文分開。如果不重讀就無法解釋這項證據，表示紀錄還沒有準備好進入綜整階段。
4. **綜整。** 將紀錄連結到論點及其他紀錄，說明各來源是相互印證、因方法或研究對象不同而有差異，還是確實衝突。不要用模糊的折衷結論抹去歧見。
5. **複核。** 在發表或交接前重新檢查影響較大的論點，確認識別碼、連結、引用範圍、證據位置、權利限制、個人資料和狀態。完成複核的標為 `reviewed`，仍有未解決問題的標為 `needs_review`，不要讓僅僅蒐集到的內容看起來已經查證。

![讓研究閱讀紀錄長期可用的四項檢查](/blog-assets/zh-Hant/keep-durable-research-reading-log/workflow-diagram.svg "記錄來源資訊與證據位置，區分引文和解讀，並再次查證")

如果綜整時發現證據缺口，或來源出現新版本，就需要回到蒐集或查證階段。狀態描述的是紀錄的處理進度，不是來源的聲望或價值。

## 穩定識別碼與連結的限制

來源有 DOI 時優先使用，並以 `https://doi.org/10.xxxx/xxxxx` 這類完整 URL 呈現。實際存取的 URL 也應另外保存，因為它能標明你查閱的是哪個副本、典藏庫或介紹頁面。

持久性仰賴註冊資訊持續維護，並不保證存取權限、補充資料不變，或被引用的頁面始終可用。沒有註冊識別碼時，應記錄完整的書目資訊、版本、URL 和存取日期；適當時，也可保存取得許可的封存副本。

來源有多個版本時，明確記錄實際讀過哪一版，並連結版本之間的關係。不要直接把預印本筆記替換成最終論文，同時假定引文、頁碼和結果完全相同。

## 著作權與隱私界線

建立閱讀紀錄不等於取得複製來源的許可。只保存必要的最少摘錄，保留出處與位置，並連結至獲授權的副本，而非重新散布全文。著作權例外會因地區和用途而異。美國著作權局說明，合理使用須依具體情況判斷，並不存在固定的「安全字數」或比例。分享前，應檢查授權條款、機構政策及適用法律。

筆記可能包含訪談引文、參與者 ID、電子郵件地址、健康資訊，或對個人的敏感評價。盡量減少蒐集，將需要存取控制的材料分開管理，適當時使用假名化識別碼，並在匯出時移除秘密資訊。只保留與明確目的相稱、相關且必要的資料。這也是歐盟《一般資料保護規則》中資料最小化原則的要求；即使該規則不直接適用，這個思路仍可作為日常管理的參考。

## 匯出、備份與還原

不要讓某一個應用程式成為讀取紀錄的唯一途徑。按固定週期，以及在重要階段結束時，以有文件說明的格式匯出。

| 格式 | 適合用途 | 保存注意事項 |
| --- | --- | --- |
| UTF-8 純文字或 Markdown | 方便人閱讀的個別紀錄和文字摘要 | 明確保留連結與欄位名稱，避免只有特定工具支援的擴充語法 |
| CSV | 平面表格與試算表之間的資料交換 | 說明編碼、分隔符號、換行，以及清單等內容的跳脫規則 |
| JSON | 結構化欄位、陣列與機器處理 | 驗證匯出檔案，並保留簡明的資料字典 |
| PDF/A 或可搜尋的 PDF | 複核或交接時點的固定快照 | 用於查閱，不應成為唯一可編輯或機器可讀的來源檔 |

匯出副本獨立於工作系統存放，才算備份。在不同位置保存副本和獲授權的附件，定期將部分紀錄還原到乾淨資料夾。檢查識別碼、Unicode 字元、換行和紀錄關聯是否完整。檢查碼能發現檔案變動，不能證明引文正確或紀錄完整。

用 `RL-2026-0042.md` 這類內部 ID 命名，不只用標題。清單列出紀錄數、匯出日期、欄位結構版本、附件、排除的受限資料和檢查碼方法。美國國會圖書館建議選格式時考量長期保存及可存取性。規格公開且有文件說明的格式，可以降低對特定供應商的依賴，但仍然需要檢查和遷移。

## 專案結束時的交接

專案結束時，準備不需要原軟體或負責人憑記憶解釋的交接資料套件：

1. 至少各包含一種人可讀格式與一種結構化格式的閱讀紀錄匯出檔；
2. 一份 README，說明研究問題、範圍、日期區間、欄位結構、狀態意義、標籤詞彙和資料夾配置；
3. 論點索引，將每個主要論點連結到支持、限定和反駁它的紀錄；
4. 檔案清單，列出檔案、版本、檢查碼、授權和存取限制；
5. `needs_review` 紀錄、失效或受限連結、缺漏來源及未解決歧見的列表；
6. 最近一次還原檢查的日期和方法，以及下次複核的負責人和日期。

保留不確定性。明確標為未解決的紀錄，比看似完善卻找不回證據的結論更可靠。

## 總結

長期可用的研究閱讀紀錄，保留的不只是引用。它能準確辨識來源及版本、區分原文和你的解釋、標明證據位置、將證據連結到論點，並呈現限制條件與複核狀態。再加上開放格式匯出、通過還原檢查的備份，以及清楚的交接資料，即使原專案和原軟體已經不在，這些推理過程仍然可以繼續使用。

## 常見問題

### 只記錄 DOI，就足以讓閱讀筆記長期可用嗎？

不夠。DOI 有助於辨識和解析來源，但筆記仍需包含版本、證據位置、存取日期、脈絡、論點連結和複核狀態。它也不能取代合法備份，或保證全文始終可存取。

### 每一處重點標示都應該變成一筆紀錄嗎？

不必。應篩選與研究問題、方法選擇或論點相關的證據。未經篩選的重點標示會累積複核負擔，讓重要證據更難找到。

### 改寫時也需要記錄頁碼或章節嗎？

需要。改寫仍然依賴來源。盡可能記錄精確位置，讓複核者可以比對你的表述與原始脈絡。

### 連結失效了怎麼辦？

先解析穩定識別碼，查找註冊中繼資料或官方典藏庫，再新增定位資訊，同時保留舊的存取歷程。如果無法找回來源，應將紀錄標為 `needs_review`，並且不要用它來支持關鍵論點。

### 應該多久複核一次閱讀紀錄？

在進行綜整、發表影響較大的論點，以及交接之前複核。長期專案也應定期重新檢查可能變動的網頁來源和持續更新的資料集。
